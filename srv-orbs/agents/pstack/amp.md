# pstack in Amp

pstack skills use Cursor names. In Amp, read this file once per thread, then map each Cursor name in a skill with the tables below. `<pstack>` means `/home/user/.config/agents/skills/pstack/`, the folder that holds `skills/`, `agents/`, and `docs/`. The orb image installs pstack there for every repository, and this file at `/home/user/.config/agents/pstack/amp.md`. If a Cursor field has no row, drop it and say so. Never pass a field or value the tool schema rejects.

Repository guidance wins. When a pstack step conflicts with an `AGENTS.md` file or with Amp's rules for actions that need approval, follow `AGENTS.md` and Amp, and say which step you changed. For example, pstack lets you push and message people without asking, but Amp still needs approval to push. Run the checks the repository's `AGENTS.md` requires before every commit and pull request.

## Tools

| Cursor                                                     | Amp                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Task`                                                     | `Task`. It takes `prompt`, `description`, `mode` (`wait`, the default, or `async`), and `id`. It has no `subagent_type`, `model`, or `readonly`. Subagents cannot spawn subagents.                                                                                  |
| `AskQuestion`                                              | `ask_user_choice`, with 2 to 5 options. Send each independent question as its own call, all in one response. For an open question, ask in plain text and end your turn.                                                                                             |
| Open a todolist                                            | Amp has no todo tool. Keep the list in your reply and update it at each phase. Use `set_thread_status` for the current step when you have it.                                                                                                                       |
| Run another pstack skill (`/name` or "the **name** skill") | Call the `skill` tool with the bare name, such as `poteto-mode`. If it is not listed, `Read` `<pstack>/skills/<name>/SKILL.md` and follow it. When you tell the user how to start a skill, write "use the poteto-mode skill". Amp has no slash commands for skills. |
| `Read`                                                     | `Read` when you have it. Otherwise read the file with `shell_command`.                                                                                                                                                                                              |
| `Grep`, `Glob`                                             | `shell_command` with `rg` or `rg --files`.                                                                                                                                                                                                                          |

| `readonly: false`                | `Task`.                                                                                                                                                                                                                                                                                                                                                                                                                                       |

| `resume`                         | `Task` with the earlier subagent's `id`. pstack's rule still holds: spawn a fresh `Task` by default, and continue an earlier one only in the cases poteto-mode's Subagents section names.                                                                                                                                                                                                                                                     |
| `environment: "cloud"`           | A `Task` that works in its own worktree. The brief tells it to run `git worktree add .worktrees/<slug> <base>` and to work only there. If the repository does not ignore `/.worktrees/`, add it to `.git/info/exclude` first. A worktree holds only committed files; pstack lives outside the repository at `<pstack>`, so the worker can read it from any worktree. Use `create_thread` with `executor: "orb"` only when the user asks for separate machines. An orb starts from the default branch and cannot see unpushed work. |
| `environment: "local"`           | Omit. `Task` subagents share this checkout.                                                                                                                                                                                                                                                                                                                                                                                                   |
| `cloud_base_branch: <b>`         | Tell the worker to use `<b>` as the worktree base.                                                                                                                                                                                                                                                                                                                                                                                            |
| `file_attachments`               | List the paths in the brief.                                                                                                                                                                                                                                                                                                                                                                                                                  |

Subagents that write code at the same time need separate files or separate worktrees.

### poteto-agent preamble

```text
You are a poteto-mode delegate. Before any other work, read /home/user/.config/agents/skills/pstack/skills/poteto-mode/SKILL.md in full, including its Principles section, then read /home/user/.config/agents/pstack/amp.md. Read a leaf principle-* skill in full whenever you apply that principle. The parent owns the playbook and the todo list. Do only the task below and report what you changed and how you verified it.
```

## Models

Every Amp `Task` runs on the model and reasoning effort of the thread that starts it, and your model routing decides which provider serves it. A subagent cannot choose its own model, effort, or fast mode. Model Routing can also send several model names to one provider model. When it serves every request with one model, a panel runs on that model whatever the skill asks for.

| Cursor                                                                                                                                                                              | Amp                                                                                                                                                                                                                                                                                                                                 |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A model slug in a `Task` call, such as `claude-opus-5-5-xhigh` or `grok-4.7-xhigh-fast`                                                                                             | Omit it. Say once per run that every subagent runs on the thread's model.                                                                                                                                                                                                                                                           |
| Picking each subagent's reasoning level and fast or standard speed                                                                                                                  | Skip it. The thread's mode sets effort for every subagent.                                                                                                                                                                                                                                                                          |
| A panel that relies on different model families (`arena` runners and cross-judge, `architect` runners, `interrogate` reviewers, the different-family review in `show-me-your-work`) | Run the same number of independent `Task` calls. Give each its own brief and make sure none sees another's output. Where a skill labels a member by model, write the thread's model. In the reply, say that the panel ran on one model, so agreement between its members is weaker evidence than it would be across model families. |
| The `pstack-models.mdc` rule, `~/.cursor/rules/pstack-models.mdc`                                                                                                                   | None. Every role uses the thread's model. Treat a lookup of a role's line as "the line is missing" and keep the skill's other steps.                                                                                                                                                                                                |

## setup-pstack

Amp has no per-role model setting, so skip steps 1 to 6 with the line `Skipped in Amp: per-role models. Every subagent runs on the thread's model.` To change that model, use the Amp mode picker, **Tune Modes**, or **Model Routing** in Amp settings. Then run steps 7 and 8 as written.
